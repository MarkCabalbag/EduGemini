## Current status

**Phase:** building. **Active milestone:** M0, in progress. **Last updated:** 2026-11-17

All docs are approved. Code is in `apps/api`, `apps/web`, `packages/shared` and `packages/ai`. The API has sign-up, sign-in, sign-out, `/me`, create, list, get, edit, archive and restore class (the list is for instructors; a student can get a class they are approved in), join by code for students (`POST /api/join`), the join-link preview (`GET /api/join/{code}`), join approval for instructors (the toggle, the People list with counts, approve, decline, reverse, remove, and approve all pending), and the student's Enrolled list (`GET /api/me/enrollments`). For instructors the API also has assignments: create a draft, list, get, edit a draft, and publish; an approved student can list and get the published ones. The web app has the landing, sign-up, sign-in, Terms, Privacy, join-link and not-found pages. Instructors have a class dashboard (with a "Show archived" switch), a create-class form and a class page with three sections, Overview (the code and join link, Edit class details, and Archive or Restore), Assignments (drafts above published ones, a New assignment button, and the five-step wizard: Basics, Criteria, Due date and scoring, Rules, Review) and People (join approval, the pending, approved, declined and removed lists, and a confirm dialog before removing); students have a dashboard with a code box to join a class and a list of their classes with status chips, and a class page (name, details, instructor name, and the published assignments, each opening an assignment page with the instructions, criteria and the AI disclosure line; a Pending student sees only "Pending approval"). The API also has the storage adapter (put, get, signed link, remove, exists) with a local and a Supabase version, and uploads use it: a student opens an upload and sends files (PDF, JPEG or PNG checked by content, 10 MiB each, ten per upload). The student assignment page has the upload control: files are checked when chosen, images are made smaller in the browser, and each file is sent on its own. Nothing finalizes an upload yet, so no submission is made. The upload also enforces the rest of the file limits: a PDF is opened to count its pages (20 at most), the files of one upload may add up to 15 MB, and the upload area shows all four limits and names the one a file went over. Finalize now makes the submission: the student assignment page has a "Submit files" button (enabled when every file is stored), and the receipt (state, time, files) replaces the upload control and shows again when the student comes back (`GET /api/assignments/{id}/me`). A submitted student is queued for grading: finalize now sends a `grade.submission` job, and the worker grades it on the fake Gemini (the grading engine core, below), and the student page shows the result (AI-11): the page asks again every 5 seconds while the receipt says "Grading in progress", and when the grade is ready it shows the AI-generated chip, the score in the assignment's format and the feedback, with the disclosure line. A student whose submission needs manual review sees "Submitted, awaiting instructor review" and no score. A letter assignment shows "87 / 100" until AI-05 adds the letter. A resubmission works through the API and uses one attempt, but the page has no control for it yet. When the due date has passed and late work is closed, opening or finalizing an upload is refused (`LATE_CLOSED`) unless the instructor allowed that student (the instructor's control is SUB-10), and a student who has not submitted sees "Closed" and the reason in place of the upload control. Upload reliability (SUB-04): each file in the upload control shows its progress in percent; a student who reloads or comes back to an upload that is still open sees the files already stored in it, ready to submit, and can remove any stored file; and the API deletes uploads left open for 24 hours, with the `staged.cleanup` job, which runs once when the API starts and then every hour. That job is one of two on the pg-boss worker that now runs inside the API process (FND-09); the other, `storage.cleanup`, deletes the objects queued in `storage_deletions` (every 5 minutes and at start). The API does not start unless `pnpm db:boss:init` has installed pg-boss's schema. The API can also store an instructor's Gemini key, encrypted (KEY-01): a service only, with no route or screen yet. An instructor can regenerate or disable a class's join code from the Class code card on Overview (CLS-08). An instructor can edit a published assignment (ASG-05): each published row has an Edit button, and the page changes the title, instructions, due date, scoring, resubmission limit and late policy; the criteria cannot be changed yet. The header has a bell with the unread count, and there is a Notifications page (NTF-01); nothing sends a notification yet. An instructor can save, replace and remove a Gemini key on Settings > AI (KEY-02, KEY-04, KEY-06); nothing checks the key with Google yet (KEY-03), so its status stays empty.
