## Current status

**Phase:** building. **Active milestone:** M0, in progress. **Last updated:** 2026-11-16

All docs are approved. Code is in `apps/api`, `apps/web`, `packages/shared` and `packages/ai`. The API has sign-up, sign-in, sign-out, `/me`, create, list, get, edit, archive and restore class (the list is for instructors; a student can get a class they are approved in), join by code for students (`POST /api/join`), the join-link preview (`GET /api/join/{code}`), join approval for instructors (the toggle, the People list with counts, approve, decline, reverse, remove, and approve all pending), and the student's Enrolled list (`GET /api/me/enrollments`). For instructors the API also has assignments: create a draft, list, get, edit a draft, and publish; an approved student can list and get the published ones. The web app has the landing, sign-up, sign-in, Terms, Privacy, join-link and not-found pages. Instructors have a class dashboard (with a "Show archived" switch), a create-class form and a class page with three sections, Overview (the code and join link, Edit class details, and Archive or Restore), Assignments (drafts above published ones, a New assignment button, and the five-step wizard: Basics, Criteria, Due date and scoring, Rules, Review) and People (join approval, the pending, approved, declined and removed lists, and a confirm dialog before removing); students have a dashboard with a code box to join a class and a list of their classes with status chips, and a class page (name, details, instructor name, and the published assignments, each opening an assignment page with the instructions, criteria and the AI disclosure line; a Pending student sees only "Pending approval"). The API also has the storage adapter (put, get, signed link, remove, exists) with a local and a Supabase version, and uploads use it: a student opens an upload and sends files (PDF, JPEG or PNG checked by content, 10 MiB each, ten per upload). The student assignment page has the upload control: files are checked when chosen, images are made smaller in the browser, and each file is sent on its own. Nothing finalizes an upload yet, so no submission is made. The upload also enforces the rest of the file limits: a PDF is opened to count its pages (20 at most), the files of one upload may add up to 15 MB, and the upload area shows all four limits and names the one a file went over. Finalize now makes the submission: the student assignment page has a "Submit files" button (enabled when every file is stored), and the receipt (state, time, files) replaces the upload control and shows again when the student comes back (`GET /api/assignments/{id}/me`). A submitted student is queued for grading, but nothing grades yet (no job queue), so the receipt stays at "Grading in progress". A resubmission works through the API and uses one attempt, but the page has no control for it yet. When the due date has passed and late work is closed, opening or finalizing an upload is refused (`LATE_CLOSED`) unless the instructor allowed that student (the instructor's control is SUB-10), and a student who has not submitted sees "Closed" and the reason in place of the upload control. Upload reliability (SUB-04): each file in the upload control shows its progress in percent; a student who reloads or comes back to an upload that is still open sees the files already stored in it, ready to submit, and can remove any stored file; and the API deletes uploads left open for 24 hours, with a sweep that runs once when the API starts and then every hour, from a timer in `main.ts` (the job queue, FND-09, will replace the timer).
