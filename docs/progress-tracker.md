## Current status

**Phase:** building. **Active milestone:** M0, in progress. **Last updated:** 2026-11-16

All docs are still "Draft for review". Code is in `apps/api`, `apps/web`, `packages/shared` and `packages/ai`. The API has sign-up, sign-in, sign-out, `/me`, create, list, get, edit, archive and restore class (the list is for instructors; a student can get a class they are approved in), join by code for students (`POST /api/join`), the join-link preview (`GET /api/join/{code}`), join approval for instructors (the toggle, the People list with counts, approve, decline, reverse, remove, and approve all pending), and the student's Enrolled list (`GET /api/me/enrollments`). For instructors the API also has assignments: create a draft, list, get, edit a draft, and publish; an approved student can list and get the published ones. The web app has the landing, sign-up, sign-in, Terms, Privacy, join-link and not-found pages. Instructors have a class dashboard (with a "Show archived" switch), a create-class form and a class page with three sections, Overview (the code and join link, Edit class details, and Archive or Restore), Assignments (drafts above published ones, a New assignment button, and the five-step wizard: Basics, Criteria, Due date and scoring, Rules, Review) and People (join approval, the pending, approved, declined and removed lists, and a confirm dialog before removing); students have a dashboard with a code box to join a class and a list of their classes with status chips, and a class page (name, details, instructor name, and the published assignments, each opening an assignment page with the instructions, criteria and the AI disclosure line; a Pending student sees only "Pending approval"). The API also has the storage adapter (put, get, signed link, remove, exists) with a local and a Supabase version; no route or screen uses it yet.

Web: the student dashboard lists each class with a status chip (Approved, Pending approval, Declined, Archived) and only an approved class opens; the student class page shows the details and the instructor name, and a pending student sees only the class name and "Pending approval"; a class just joined appears in the list at once

Not checkable yet: the effects on the gradebook, review queue and tracker (those screens do not exist)
- [x] Archive and restore a class (EG-CLS-10). API: `POST /classes/{id}/archive` and `/restore` for the owning instructor, both idempotent (archiving again does not move the date; restore clears `archived_at` and `retention_notice_at`); another instructor, a student or a missing class gets `NOT_FOUND`. An archived class is read-only: the approval switch, the decision route and approve all pending answer `CLASS_ARCHIVED` (409), the People list still reads, its join code reads as invalid, and approved students still see it, marked Archived. Web: the class page shows an Archived chip, hides the class code while archived, and has a card at the bottom of Overview: Archive class (asks first, in a confirm dialog) or Restore class (no question); People on an archived class has the switch disabled and no student actions; the dashboard has a "Show archived" switch that swaps the list between active and archived classes (always shown, so an instructor whose only class is archived can still reach it), and archived cards carry an Archived chip. Assignment writes on an archived class answer `CLASS_ARCHIVED` (ASG-01). Not checkable yet: the review queue excluding archived classes, and uploads (those do not exist)
- [x] Create assignment, instructor side (EG-ASG-01). API (API Spec ASG-01 to ASG-04, ASG-06): `POST /classes/{id}/assignments` makes a draft from a title alone (defaults: 3 resubmissions, late accepted, UTC, points out of 100, a due date a week ahead); `GET /classes/{id}/assignments` lists by nearest due date with an optional status; `GET /assignments/{id}`; `PATCH /assignments/{id}` edits a draft (a published or archived one answers `CONFLICT` until ASG-04); `POST /assignments/{id}/publish` needs criteria, is idempotent, and returns the warnings `DUE_IN_PAST` and `NO_VALID_KEY` without blocking. Percentage and letter assignments are always out of 100. Another instructor, a student or a missing item gets `NOT_FOUND`; an archived class answers `CLASS_ARCHIVED` for every write. Web: the class page has an Assignments section (Drafts with Resume above Published; "Create your first assignment." when empty; no New or Resume on an archived class) and the five-step wizard at `/classes/:id/assignments/new` and `/assignments/:id/edit?step=N`. Step 1 makes the draft in the browser's time zone, every later step saves it ("Draft saved"), and Review has Save as draft and Publish, after which the list shows a notice with the warnings. The due date is typed on the clock of the chosen zone and stored in UTC (Intl only, no library). Not built: reference files (ASG-07), labels (ASG-11), counts on rows, delete and archive (ASG-10), a screen for a published assignment
- [x] Students see published assignments (EG-ASG-03). API: `GET /classes/{id}/assignments` and `GET /assignments/{id}` now answer an approved student (the owning instructor as before), through `assignment.view` as `member`. A student only ever gets published assignments: the list leaves out drafts and archived ones (a `status` filter that excludes them gives an empty page), and opening one gives `NOT_FOUND`. A pending student gets `ENROLLMENT_PENDING`, checked before the draft check; declined, removed, strangers and the Super Admin get `NOT_FOUND`. An archived class stays readable. The detail includes the instructions and criteria. The two reads have no role check in the route, as get-class has, and the service decides; the writes still refuse a student first. Web: the student class page lists the published assignments (title and due date in the student's own time zone, "No assignments yet." when empty, "Show more assignments"), each a link to `/assignments/:id`, a page with the title, due date, scoring, the late policy, the instructions, the criteria, an Archived chip for an archived class, and the UX Brief disclosure line; an instructor, a draft, a missing assignment and a pending student all get the "couldn't find that page" screen. Not built: the status chip on each row and `my` (the submission tickets), "N resubmissions left" (SUB-09), the upload control (SUB-01), reference files (ASG-07), labels, and the class stats card
- [x] Edit class details (EG-CLS-07). API (API Spec CLS-04): `PATCH /classes/{id}` changes the name, description, section, subject and room of the owning instructor's class. A field left out is unchanged, a blank optional field is cleared (stored as null), the name cannot be blank, and any other field (the join code, the approval switch) is refused with `VALIDATION`. The code, the link and the students are not touched. An archived class answers `CLASS_ARCHIVED`; another instructor, a student or a missing class gets `NOT_FOUND`. Web: Overview has a Class details card with "Edit class details", which opens a dialog with the five fields filled in and Save changes and Cancel. A problem shows under its field or at the top of the dialog, Cancel changes nothing and the dialog opens again with the saved details, and saving closes it with the new name and details on the page. The card is not shown on an archived class
- [x] Storage adapter (part of EG-FND-06). `StorageAdapter` (API Spec C.4): `put` streams, counts the bytes and their SHA-256, refuses a file over the cap with `FILE_TOO_LARGE` and stores nothing, and replaces a path stored again; `get`, `signedUrl` (5 minutes by default; a missing object is `NOT_FOUND`), `remove` (a missing object counts as removed) and `exists`. `createStorage(env)` picks the driver from `STORAGE_DRIVER`. Local driver: files under `STORAGE_LOCAL_DIR`, a path or bucket that climbs out of its folder is refused, and the link is signed with `SESSION_SECRET` and served by `GET /api/dev/files`, which is registered only for the local driver (checked on the running API: a fresh link gives the file, a changed signature gives 404). Supabase driver: the Storage REST API through `fetch`, so no new library; any failure is `SERVICE_UNAVAILABLE` for storage. No route or screen uses the adapter yet. Not checked: the Supabase driver against a real bucket, because its tests replace `fetch` and `.env` has no `SUPABASE_URL` or service-role key
